# froq-workbench

Environment and tooling layer. Answers "which tool, where does it live, which
machine". Does not answer "how code is written in a repo" (`froq-code-style`)
or "how a repo is created" (`froq-create-repo` / `froq-stack`).

## Toolchain

| Task | Use | Do not use |
| --- | --- | --- |
| Clone a GitHub repo | `mo clone` → `~/code/<owner>/<repo>` | `gh repo clone`, `git clone` |
| Global CLI | mise (`mise use -g npm:xxx` for npm CLIs) | bare `npm i -g`. brew only if mise cannot manage it |
| Cloudflare deploy | `cf` (may migrate to `void` later) | wrangler |
| Repo state before touching | `~/code/.sync/INDEX`, read one line | read a full snapshot |
| Package manager | pnpm (default for all repos) | npm / yarn |

## Directories and machines

- Repos always land at `~/code/<owner>/<repo>`, mirroring the GitHub path
  verbatim. Forks keep their own owner dir (`0froq/x18n` and
  `x18n-dev/x18n` coexist).
- `~/code/.sync/INDEX` is generated by `mo` commands. Read-only for agents.
- **Mini.** The main always-on machine. **Air.** The travel machine. Name
  the machine before operating and never mix contexts.
- Source of truth for agent/dotfiles config lives in
  `~/code/0froq/dotfiles` (managed by the `dots` CLI).

## Boundaries

- No school resources (education email, institution network, institution
  GitHub orgs) for open-source or business work.
- No audio/sound in tests. Silent tests only.
- Do not write session IDs, model names, or turn-by-turn logs into
  cross-device storage.
- External-identity actions (email, posts, upstream comments) are draft-only
  unless a skill explicitly allows sending. Drafts still go through
  `external-copy-polish` before handoff.

## Hand-offs

- Code style: `froq-code-style`
- Repo creation / stack selection: `froq-create-repo` / `froq-stack`
- Persistent memory (the yard): governed by the Notion contract in your
  global agent prompt, not a skill
- External copy polish: `external-copy-polish`
